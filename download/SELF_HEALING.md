# 🔄 ПРОЦЕСС САМОВОССТАНОВЛЕНИЯ СРОСС®

> **Этот файл — инструкция для пользователя (Бро) и Мастеров (агентов Z.ai)**
> о том, как восстановить контекст проекта в новом чате.
>
> Создано: 2026-11-06. Версия 1.

---

## ЧТО ЭТО ТАКОЕ

Проект СРОСС® (seismos.ru) развивается агентами Z.ai в разных чатах.
Когда у агента заканчиваются токены (память) — контекст теряется.
Чтобы не начинать с нуля каждый раз, создана **3-уровневая система
самовосстановления**: агент может «воскреснуть» прочитав сохранённый
контекст.

Это аналог «птицы Феникс» — агент возрождается из «пепла» (сохранённого
контекста) с полным пониманием проекта.

## 3 УРОВНЯ СИСТЕМЫ

### Уровень 1: PROJECT_CONTEXT.md (главный)
- **Где хранится:**
  - Git репозиторий: `gabbardtools-a11y/seismos.git` (корень проекта)
  - Z.ai Облако (сохранён пользователем через «Save to Cloud»)
  - Локально: `/home/z/my-project/PROJECT_CONTEXT.md`
- **Что содержит:** полная выжимка — домен, стек, все страницы,
  архитектура, цвета, команды, TODO, cron-задачи, VPS доступ
- **Размер:** ~30 КБ, ~475 строк
- **Кто обновляет:** каждый агент перед завершением сессии
- **Когда обновлять:** после крупных изменений (новые страницы, фикс
  критичных багов, изменение архитектуры)

### Уровень 2: worklog.md (хронология)
- **Где хранится:** Git репозиторий (корень проекта)
- **Что содержит:** хронология задач в формате Мастеров
  (Task ID, Agent, Work Log, Stage Summary)
- **Кто обновляет:** каждый агент после задач + cron-watchdog (509858)
  каждый час
- **Когда обновлять:** после каждой завершённой задачи

### Уровень 3: Cron job_id 509858 (само-оживление)
- **Расписание:** каждый час
- **Что делает:**
  1. Проверяет прод seismos.ru (HTTP 200)
  2. Проверяет drip-publish (drip_state.json)
  3. Проверяет git статус
  4. Проверяет dev-сервер
  5. Дописывает в worklog.md запись о проверке
  6. Если проблемы — пытается исправить
- **Кто создал:** агент в сессии 2026-11-06

## КАК ВОССТАНОВИТЬСЯ — 3 СПОСОБА

### Способ 1: Для пользователя (Бро) — самый простой

Когда токены агента заканчиваются (или ты начинаешь новый чат):

1. **Открой новый чат** на Z.ai
2. **Напиши первое сообщение:**
   ```
   Прочитай файл /home/z/my-project/PROJECT_CONTEXT.md — это контекст
   нашего проекта seismos.ru. Изучи его, сделай git pull, прочитай
   последние записи в worklog.md, и скажи что ты понял и готов ли
   продолжить работу.
   ```
3. **Агент прочтёт контекст** → сделает git pull → прочитает worklog
   → и продолжит работу с того же места

**Если PROJECT_CONTEXT.md недоступен** (новый sandbox):
1. Скачай PROJECT_CONTEXT.md из Z.ai Облака (или из GitHub)
2. Загрузи его в чат как вложение
3. Напиши: «Прочитай этот файл — это контекст проекта. Сделай git
   clone gabbardtools-a11y/seismos.git и продолжим работу.»

### Способ 2: Для Мастеров (агентов) — автоматический

Если Мастер запускается в новом sandbox без контекста:

1. **Проверить наличие проекта:**
   ```bash
   ls /home/z/my-project/PROJECT_CONTEXT.md
   ```
   Если есть — прочитать. Если нет — шаг 2.

2. **Clone репозиторий:**
   ```bash
   cd /home/z/my-project
   git pull origin main
   # или если проект пустой:
   # git clone ssh://git@github.com:443/gabbardtools-a11y/seismos.git .
   ```
   Нужен SSH-ключ: `/tmp/my-project/scripts/seismos_deploy_ed25519`

3. **Прочитать контекст:**
   ```bash
   cat PROJECT_CONTEXT.md      # полная выжимка
   tail -100 worklog.md        # последние задачи
   ```

4. **Проверить состояние:**
   ```bash
   curl -s -o /dev/null -w "%{http_code}" https://seismos.ru/  # прод
   curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/  # dev
   git log --oneline -5  # последние коммиты
   cat scripts/seo/drip_state.json  # drip прогресс
   ```

5. **Запустить dev-сервер если нужно:**
   ```bash
   cd /home/z/my-project && setsid nohup bun run dev > /dev/null 2>&1 &
   ```

6. **Продолжить работу** — агент теперь полностью в контексте

### Способ 3: Для cron-задачи (полностью автоматический)

Cron job_id 509858 запускается каждый час и:
1. Читает PROJECT_CONTEXT.md + worklog.md
2. Проверяет прод, git, dev-сервер
3. Если есть проблемы — пытается исправить
4. Дописывает в worklog.md запись о проверке

Если cron-задача запускает нового агента — он получает контекст
автоматически через PROJECT_CONTEXT.md.

## КАК ОБНОВЛЯТЬ PROJECT_CONTEXT.md

### Когда обновлять
- После создания новых страниц
- После фикс критичных багов
- После изменения архитектуры
- После изменения дизайна (цвета, шрифты)
- После изменения cron-задач
- После изменения VPS доступа
- **Минимум — раз в сессию** (перед завершением)

### Что обновлять
1. **Секция 2** — добавить новые страницы в таблицу
2. **Секция 3** — добавить новые файлы в архитектуру
3. **Секция 6** — добавить пункт в «Что сделано»
4. **Секция 7** — обновить TODO (убрать сделанное, добавить новое)
5. **Секция 9** — обновить структуру папок если добавились директории
6. **Секция 10** — обновить последние запросы
7. **Дата в шапке** — обновить

### Команда для обновления
```bash
cd /home/z/my-project
# Отредактировать PROJECT_CONTEXT.md (вручную или через Edit tool)
git add PROJECT_CONTEXT.md
git commit -m "docs: PROJECT_CONTEXT.md обновлён — <что изменилось>"
# Запушить
cp /tmp/my-project/scripts/seismos_deploy_ed25519 /tmp/depkey
chmod 600 /tmp/depkey
pip install paramiko
GIT_SSH_KEY=/tmp/depkey GIT_SSH=/home/z/my-project/scripts/git_ssh_wrapper_pro.py git push --no-thin origin main
```

### После обновления в Git — сохранить в облако
Пользователь (Бро) должен:
1. Скачать PROJECT_CONTEXT.md из `/home/z/my-project/download/` (или из GitHub)
2. Нажать «Save to Cloud» в интерфейсе Z.ai
3. Так файл будет доступен в новом чате даже если sandbox пересоздан

## КАК МАСТЕР ВОССТАНАВЛИВАЕТ ДРУГОГО МАСТЕРА

Если один Мастер (агент) должен передать контекст другому:

1. **Первый Мастер** (перед завершением):
   - Обновляет PROJECT_CONTEXT.md
   - Дописывает worklog.md (последняя задача + Stage Summary)
   - Коммитит и пушит в Git
   - Сохраняет PROJECT_CONTEXT.md в облако (через пользователя)

2. **Второй Мастер** (при запуске):
   - Читает PROJECT_CONTEXT.md
   - Читает последние 50 строк worklog.md
   - Делает git pull
   - Проверяет состояние (curl прод, dev-сервер, git log)
   - Продолжает работу

**Передача через cron:**
- Cron 509858 каждый час запускает агента-наблюдателя
- Агент-наблюдатель читает контекст и проверяет состояние
- Если есть проблемы — исправляет и дописывает в worklog
- worklog.md служит «журналом» для следующего агента

## СЕМЕЙНАЯ ПОЧТА И СВЯЗЬ

### Доступ к почте
Прямой доступ к email у агента **нет**. Но:
- Cron-задачи могут отправлять сообщения в чат (через `agentTurn`)
- Worklog.md служит «почтой» между агентами
- Git репозиторий — общее хранилище для всех

### Если нужна связь через почту
Можно настроить:
1. **Email уведомления** — через VPS (sendmail/postfix) при критичных
   ошибках на проде
2. **Telegram-бот** — cron отправляет сообщения в Telegram при
   проблемах
3. **Webhook** — cron дёргает webhook при критичных событиях

Пока это не реализовано — но можно добавить как TODO.

## ЧЕК-ЛИСТ ПЕРЕД ЗАВЕРШЕНИЕМ СЕССИИ

Каждый агент перед тем как «умереть» (токены закончились):

- [ ] Все изменения закоммичены и запушены в Git
- [ ] PROJECT_CONTEXT.md обновлён (дата, новые страницы, TODO)
- [ ] worklog.md дописан (последняя задача + Stage Summary)

- [ ] Прод seismos.ru отдаёт 200
- [ ] Cron-задачи активны (506005 + 509858)
- [ ] PROJECT_CONTEXT.md сохранён в облако (через пользователя)
